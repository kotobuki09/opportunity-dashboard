# Opportunity Scout

Personal opportunity workspace for research fellowships, grants, accelerators, startup programs,
AI gigs, tenders, and other opportunities. The live dashboard is at
**https://kotobuki09.github.io/opportunity-dashboard/**.

## What it does

- **Overview** — actionable deadlines, urgent items, and a transparent priority heuristic.
- **Explore** — search, category/project/deadline/status filters, sortable table, and responsive mobile cards.
- **Pipeline** — Kanban columns with drag-and-drop and status selectors for application progress.
- **Calendar** — Vietnam-time deadlines grouped by month, downloadable .ics files with a one-day alert.
- **Personal work** — per-opportunity status, private notes, next actions, and a checklist with a confirmed reset action.
- **Data integrity** — announced-but-not-open, rolling, missed cut-off, unknown, and expired are separate states. A source without a verified_at date is clearly marked as *not documented as checked*, not automatically considered invalid.

The priority score is **an explainable sorting aid**, not a grant award probability or an
eligibility assessment. Financial values are source-provided headline amounts and should
not be interpreted as guaranteed funding.

## Privacy and persistence

Data about the opportunities comes from data/seen.json and is compiled into the public app.
Do **not** add personal email addresses, private application documents, or secrets to that file.

Personal statuses, notes, checklists, and next actions remain in each visitor's browser
at localStorage key oppScout.v1. Browser export uses a version-2 JSON document;
import supports existing version-1 exports. Export/import is a manual backup workflow:
**there is no account login, shared workspace backend, or automatic cross-device sync**.
Each opportunity can be reset individually after confirmation.

## Production readiness V3

- **Data quality workbench**: a dedicated source-verification queue, metadata-normalization queue, availability/cut-off queue, field-level issue badges, next actions and exportable public CSV. The sidebar and overview surface outstanding reviews.
- **Source monitoring**: Scheduled public-link reachability checks and curated NSF/Grants.gov feed discovery produce human-review artifacts. HTTP status is **not eligibility verification** and no unreviewed sources are automatically published.
- **Funding values**: Optional benefit kind keeps grants, equity, credits and prizes distinct; no misleading cross-type financial total.
- **Workflow**: All Kanban items are accessible; calendar excludes skipped/joined opportunities and offers a tracked-only view.
- **Security and privacy**: best-effort HTML CSP on GitHub Pages, no backend or account sync, status and private notes live only in local browser storage.
- **Operations**: see docs/PRODUCTION_READINESS_PLAN.md and docs/OPERATIONS_RUNBOOK.md for acceptance gates, scheduled checks, manual source review and rollback.
- **Live availability**: scheduled GitHub Action checks public HTML, JS/CSS and favicon/touch assets after deployments and every morning; browser E2E runs on each code/data release.

## Development

The app is Vite + React + TypeScript + Tailwind CSS + shadcn/ui with TanStack Table and
Recharts. It is hosted on GitHub Pages under base path /opportunity-dashboard/.

    npm ci
    npm run validate  # Validate data/seen.json against schema and dates
    npm test          # Node tests for deadline calculations, calendar, priority
    npm run lint      # ESLint
    npm run build     # TypeScript and production Vite bundle
    npm run dev       # Local development

data/seen.json is the single source of truth. See SCHEMA.md for field definitions,
data/seen.schema.json for validation, and AGENTS.md before modifying the dataset.
src/data/data.json is build-generated by scripts/gen-data.mjs and must not be edited.

The workflow .github/workflows/deploy.yml validates, tests, lints, and builds on PRs.
Commits to main deploy to GitHub Pages only when all checks pass.

## Source verification vs normalization

- **Verification** answers: has someone checked the official page recently and recorded `verified_at`? Missing, stale and invalid dates are review tasks, not proof that an opportunity is fake or ineligible.
- **Normalization** answers: are eligibility, stage, project fit, and the type of financial benefit explicit? `unknown` may be accurate if the official source does not state a benefit; the app requests human classification rather than fabricating one.
- **Availability** answers: is an intake currently open, unknown or past a rolling cut-off? True rolling programs do not need a fake closing date.
- The quality queue has independent tabs, suggested remediation and a **CSV export of public metadata only**. Per-user notes and private application checklists are never exported through this CSV.
- To update public facts, submit a reviewed change to `data/seen.json`; the browser is intentionally read-only with respect to public source records. See `SCHEMA.md` and `docs/OPERATIONS_RUNBOOK.md`.

## Quality Studio and evidence (V3.2)

The redesigned **Kiểm tra dữ liệu** workspace combines an editorial queue, filterable field-level issues, a mobile-responsive record inspector, and a non-destructive metadata proposal editor. Review status, completeness, and HTTP reachability are **three independent signals**; a green source link is not an eligibility approval. The proposal editor exports a JSON patch (or copies it) for a human to apply via a GitHub PR. Browser-local statuses, notes and checklists never leave the browser with these exports.

A scheduled official-source job refreshes the public `source-health.json` snapshot after sanitizing the monitor artifact to URL, HTTP health and status only. The bot writes **only `public/source-health.json`** and explicitly dispatches the standard Pages pipeline; it never changes `data/seen.json` or `verified_at`. On missing or stale scans, the dashboard clearly labels reachability information unavailable/outdated rather than faking healthy URLs. See `docs/OPERATIONS_RUNBOOK.md` for checks and rollback.
